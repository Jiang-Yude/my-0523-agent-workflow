Case Positioning

這不是生圖紀錄，是一條 Agent 工作流

同一件事情拆成六個節點，才會從一次性產出變成下次可重複執行的流程。

教學重點：老師不只學會叫 AI 生圖，而是把自己的素材生產流程變成可重複執行的規則。
01

文案整理

保留原本語氣，搭配咪卡形象與每張指定動作，整理成可發文、可拆卡的版本。

02

視覺生成

套用咪卡角色設定，生成直式輪播與橫式總結。
延伸閱讀：咪卡形象與指定動作示範

03

檔案管理

依日期、主題與用途命名，集中放回文章資料夾。

04

圖片縮檔

轉成 JPG，直式控在 300KB 內，橫式控在 500KB 內。

05

看板更新

把看板當成一眼驗收的工作紀錄：AI 依指定格式貼上首頁 01 與連結，就代表整條流程已跑完；格式不對就是警訊。

06

技能包沉澱

把踩雷、修正與規則寫回技能包，讓下次直接觸發。

起點：一篇脆文

原文討論 Markdown 與 HTML 的工作流分工：內部知識沉澱用 Markdown，對外溝通與視覺化用 HTML。

中段：做成輪播卡

用咪卡品牌角色，把抽象工作流轉成 7 張直式圖卡與 1 張橫式總結，方便社群傳播與教學。

終點：沉澱成技能包

把角色規格、圖卡版型、看板規則、縮檔策略寫成 mika-carousel-card。

Workflow

從對話到可重複執行的流程

每一步都不是單次操作，而是可被下次沿用的規則。

1

確認概念與貼文主張

先確認「Markdown vs HTML」不是格式鄙視鏈，而是工作流分配。

  • AI ↔ 我：Markdown
  • 我 ↔ 其他人：HTML
  • PDF 因靜態與高雜訊，不是這個流程的主要輸出
「主要不是格式誰比較香，而是工作流的差異。」
2

拆成輪播卡腳本

保留使用者原本開頭與口氣，再搭配咪卡形象設定與每張指定動作，把後段整理成能被圖卡承載的結構。

  • 封面：HTML 比 Markdown 香？
  • 年份變化：2024/2025 Markdown，2026 HTML 變多
  • 核心分工圖：AI ↔ 我 / 我 ↔ 其他人
  • 每張卡指定咪卡要做什麼：看文件、指向流程、對照格式、操作部署
  • Markdown、HTML、PDF、GitHub Pages 分段說明
這一步把「社群短文」轉成「文字腳本 + 角色動作腳本」。咪卡形象設定本身可再獨立成另一篇教學。
3

用咪卡形象照逐張生成

每張圖卡都使用咪卡定稿照作為角色參考，確保黑貓、金色眼睛、帽子與知識助理氣質一致。

  • 第 1 張：咪卡固定右下角
  • 第 2 張：不要右下角
  • 每張都要與文字或圖表互動
這一步示範「角色定妝照」如何變成長期素材生產的穩定基礎。
4

整理正式貼文資料夾

Codex 把生成圖整理到正式 Threads 貼文資料夾，建立 Markdown 貼文檔並嵌入所有圖卡。

  • 資料夾：2026-05-11-1400 Markdown 跟 HTML 工作流分工
  • 文章檔含 frontmatter、正式貼文、圖卡區、橫式總結區
  • 看板排程到 2026-05-11 14:00
Agent 的價值在生成後的整理、命名、放對位置與連動。
5

獨立成「輪播咪卡」技能包

把這次的做法拆成四份 reference 和一支縮檔腳本，主知識庫與 Codex 各放一份。

  • mika-character-lock.md：角色與帽子硬規則
  • carousel-workflow.md：輪播版型
  • posting-board-rules.md：發文看板規則
  • image-compression-rules.md：JPG 縮檔規則
「技能包不是提示詞收藏，是一套可以被反覆執行的工作流程。」
Dialogue Record

對話紀錄如何推動規則長出來

這裡保留的是教學用脈絡，而不是逐字稿。每一段都對應一個流程決策。

使用者

先確認「Markdown 跟 HTML 的差異，我覺得是工作流的分配」這個概念是否合理。

結果：確立主張，不把開頭改掉，保留「最近有大神在推 HTML 比 Markdown 香」作為社群語境。
Codex

整理貼文後段，設計 7 張咪卡輪播卡腳本，並建立生成指令檔。

結果：從文案變成卡片腳本，形成初版社群圖卡流程。
使用者

「先幫我生第一張」「依此類推 生完」。

結果：逐張生成 7 張直式圖卡，後續再補 1 張橫式總結。
使用者

提供正式貼文，要求上發文看板並整理圖片，排程時間是今天 14:00。

結果：建立正式文章檔，圖卡歸檔，更新發文看板。
使用者

提醒圖片大小：直式要 300KB 內，橫式一頁總結 500KB 內。

結果：第一次錯用 PNG 量化，後續改成 JPG 縮檔並寫回技能包。
使用者

指出發文看板不是素材堆疊區，而是一眼檢查 AI 有沒有完成指定流程的工作紀錄。

結果：修正 09:00 與 14:00 看板卡片，技能包補上「看板只放圖片01 + 文件連結」作為驗收格式。
Iteration Log

修正紀錄是技能包迭代的一部分

重點不是錯誤本身，而是把操作過程有意識地提煉成可重複使用的規則。

錯誤 1

PNG 強壓導致畫質變差

原本為了維持 PNG，把直式圖卡壓到 300KB 以內，結果需要大量色彩量化，畫面變得像單色圖。

修正 1

改成 JPG 縮檔

從原始生成圖重新輸出 JPG。直式保留原解析度並壓到 300KB 內；橫式保留 1672×941，壓到 500KB 內。

錯誤 2

看板變成素材堆疊區

發文看板原本把同一主題的多張圖都嵌進卡片，造成看板過長，也失去「一眼驗收」的作用。

修正 2

看板成為一眼驗收機制

看板只保留 圖片01.jpg 當示意圖，並連回文章檔。只要格式正確，就能快速判斷生成、歸檔、縮檔與文件整理已完成。

Teaching Use

5/23 可以怎麼教老師用 Agent

這個案例適合示範「老師如何把自己的教學風格與素材生產線封裝起來」。

1. 先有形象設定

角色不是每次重畫，而是先有定妝照、帽子規則、氣質規則。

2. 把版型寫成規則

第一張、第二張、橫式總結、文字密度、互動方式都要明確。

3. 用 Codex 執行整條流程

生成、命名、歸檔、寫文章檔、更新看板，不只是生圖。

4. 把經驗提煉成資產

技能包給 AI 用，操作手冊讓自己重跑，教學手冊讓大家學會。

一句話總結

這個案例不是「AI 幫我做圖」，而是「我把自己的隱性知識提煉出來，變成 AI 可用的技能包、自己可重跑的操作手冊，以及可以教給別人的教學案例」。

外來延伸應用可以再接 Manus 做自動發文排程或多平台發布；這裡先作為延伸方向，不放進主流程。
